# ADR 0001: 文档管理系统架构设计

## 状态

已批准

## 背景

我们需要一个文档管理系统来记录和管理各种类型的文件（代码、Markdown、JSON、富文本等），支持版本控制、标签分类和权限管理。

## 决策

### 1. 数据存储策略

**决策**：文档内容直接存储在数据库中（Text/JSON字段）

**原因**：
- 需求明确要求"文档内容可以直接导入文件"
- 适合文本类型文件（代码、Markdown、JSON等）
- 简化架构，不需要额外的文件存储服务

**实现**：
- 主文档表存储当前版本内容
- 版本表存储历史版本内容

### 2. 版本管理策略

**决策**：用户手动指定版本号

**原因**：
- 需求明确要求"用户手动指定版本号"
- 灵活，可体现业务含义（如：v1.0.0, v2.0.0）
- 简单版本追溯

**实现**：
- 文档表：存储当前版本信息
- 版本表：存储所有历史版本快照

### 3. 权限控制策略

**决策**：只有创建人可以编辑/删除文档

**原因**：
- 需求明确要求"只能创建人操作"
- 简化权限模型

**实现**：
- 在Service层校验创建人ID
- 历史版本不可编辑，只能查看或删除

### 4. 标签系统设计

**决策**：支持预设标签 + 用户自定义标签

**原因**：
- 预设标签通过字典表维护（复用现有基础设施）
- 用户自定义标签提供灵活性

**实现**：
- 标签表：存储所有标签（预设和自定义）
- 文档标签关联表：多对多关系

### 5. 历史版本记录方式

**决策**：使用独立的文档版本表

**原因**：
- 需求明确要求"可查看历史版本"，需要完整内容快照
- DataTracer只能记录diff，不能存储完整内容
- 查询效率更高

**实现**：
- 新增 `t_document_version` 表
- 存储版本号、文档ID、内容、创建人等信息

### 6. 删除策略

**决策**：硬删除

**原因**：
- 需求明确要求"删除文档以及历史版本"
- 简化数据管理

**实现**：
- 物理删除数据库记录
- 包括文档主记录和所有历史版本

## 数据库设计

### 1. 主表：t_document

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| create_user_id | BIGINT | 创建人 |
| create_time | DATETIME | 创建时间 |
| update_user_id | BIGINT | 更新人 |
| update_time | DATETIME | 更新时间 |
| deleted_flag | TINYINT(1) | 删除状态（0-未删除，1-已删除） |
| document_name | VARCHAR(100) | 文档名称 |
| document_content | TEXT | 文档内容 |
| file_type_dict_data_id | BIGINT | 文件类型（字典数据ID） |
| document_type_dict_data_id | BIGINT | 文档类型（字典数据ID） |
| version | VARCHAR(20) | 当前版本号 |

```sql
CREATE TABLE `t_document` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `create_user_id` BIGINT NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_user_id` BIGINT DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_flag` TINYINT(1) NOT NULL DEFAULT '0' COMMENT '删除状态',
  `document_name` VARCHAR(100) NOT NULL COMMENT '文档名称',
  `document_content` TEXT COMMENT '文档内容',
  `file_type_dict_data_id` BIGINT DEFAULT NULL COMMENT '文件类型（字典数据ID）',
  `document_type_dict_data_id` BIGINT DEFAULT NULL COMMENT '文档类型（字典数据ID）',
  `version` VARCHAR(20) DEFAULT NULL COMMENT '当前版本号',
  PRIMARY KEY (`id`),
  KEY `idx_t_document_name` (`document_name`),
  KEY `idx_t_document_file_type` (`file_type_dict_data_id`),
  KEY `idx_t_document_doc_type` (`document_type_dict_data_id`),
  KEY `idx_t_document_create_user` (`create_user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文档表';
```

### 2. 版本表：t_document_version

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| create_user_id | BIGINT | 创建人 |
| create_time | DATETIME | 创建时间 |
| update_user_id | BIGINT | 更新人 |
| update_time | DATETIME | 更新时间 |
| deleted_flag | TINYINT(1) | 删除状态（0-未删除，1-已删除） |
| document_id | BIGINT | 文档ID |
| version | VARCHAR(20) | 版本号 |
| document_content | TEXT | 文档内容快照 |

```sql
CREATE TABLE `t_document_version` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `create_user_id` BIGINT NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_user_id` BIGINT DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_flag` TINYINT(1) NOT NULL DEFAULT '0' COMMENT '删除状态',
  `document_id` BIGINT NOT NULL COMMENT '文档ID',
  `version` VARCHAR(20) NOT NULL COMMENT '版本号',
  `document_content` TEXT COMMENT '文档内容快照',
  PRIMARY KEY (`id`),
  KEY `idx_t_document_version_document` (`document_id`, `version`),
  KEY `idx_t_document_version_create_user` (`create_user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文档版本表';
```

## 查询索引

1. `idx_document_name` on t_document(document_name)
2. `idx_document_file_type` on t_document(file_type_dict_data_id)
3. `idx_document_doc_type` on t_document(document_type_dict_data_id)
4. `idx_document_tag` on t_document_tag(document_id, tag_id)
5. `idx_version_document` on t_document_version(document_id, version)
6. `idx_tag_name` on t_tag(tag_name)
