# Skill 管理平台 - 需求与表结构设计

## 一、总体概述

**目标**：提供一套对「Skill（技能包）」进行集中管理的平台，使 Skill 的创建、编辑、组织、分发、发布与迭代形成闭环，支撑 Agent 按需加载并稳定运行技能。

**定位**：
- Skill 是 Agent 可调用的能力单元，由一个入口描述文件（`SKILL.md`）和若干附属文件（脚本、配置、提示词、参考文档等）按目录结构组成。
- 平台不负责 Skill 的运行，只负责 Skill 的「定义、存储、组织、版本、发布、分发」。
- 平台需保证 Skill 在「编辑态」与「运行态（已发布）」隔离，避免编辑影响线上 Agent。

**角色**：
- 技能作者（创建人）：创建/编辑 Skill 及其文件、目录、版本，并自行执行上线/下线。
- 使用者（Agent 运行时）：仅消费「已上线」且「当前生效版本」的 Skill。

---

## 二、核心概念与领域模型

### 2.1 Skill（技能包）

**定义**：一个可独立命名、描述、发布与分发的技能单元，是平台的顶层管理对象。

**组成**：
- **元信息**：名称、描述、分类、标签、状态、当前生效版本。
- **文件集合**：一组按目录组织的文件（含 `SKILL.md`）。
- **版本集合**：该 Skill 的历史/当前版本。
- **发布状态**：草稿 / 审核中 / 已上线 / 已下线。

**关键属性**：
- `name`：技能名称（对应 `SKILL.md` frontmatter 的 `name`），兼作对外引用标识。
- `description`：技能描述（对应 `SKILL.md` frontmatter 的 `description`），用于触发匹配。
- `category`：分类（字典）。
- `tags`：标签，JSON 数组存储于主表（如 `["数据库","规范"]`）。
- `status`：生命周期状态。
- `currentVersion`：当前线上生效的版本号。
- `owner`：负责人，等同于创建人（`create_user_id`），不单独建列。

**业务规则**：
- 每个 Skill 必须有且仅有一个 `SKILL.md` 作为入口文件。
- 只有创建人（`create_user_id`）可编辑、维护 Skill 及其全部操作。
- Skill 删除为逻辑删除（置 `deleted_flag`）；已上线 Skill 需先下线再删除。

---

### 2.2 Skill 文件（SkillFile）

**定义**：Skill 内的单个文件实体，承载内容（Markdown / 脚本 / JSON / 配置 / 文本等）；目录关系由文件路径前缀体现，无独立目录字段。

**关键属性**：
- `path`：相对 Skill 根目录的路径（如 `scripts/run.py`、`SKILL.md`），目录即路径前缀。
- `name`：文件名。
- `fileType`：文件类型（字典：markdown / json / text / code / 其他）。
- `content`：文件内容（文本/代码，存库或对象存储）。
- `size`：内容大小。

**业务规则**：
- `SKILL.md` 为必填文件；缺失时禁止上线。
- `SKILL.md` 必须包含合法 frontmatter（`name`、`description`），保存时校验。
- 文件路径在 Skill 内唯一（同目录下同名文件互斥）。
- 文件内容支持在线编辑，保存即更新「草稿」。
- 删除文件需二次确认；删除 `SKILL.md` 不被允许（需先重建或整体删除 Skill）。

---

### 2.3 目录结构（由路径派生）

**定义**：Skill 内部的树形目录，用于组织文件、表达层级关系；目录不单独建表，由文件路径（`skill_file.file_path`）的前缀解析得出。

**业务规则**：
- 目录为文件的逻辑容器，不单独存内容；空目录在打包导出时无意义，不持久化。
- 支持多级嵌套（建议不超过 5 层，需约束）。
- 目录的创建/重命名/移动/删除，均等价于对 `file_path` 做前缀批量操作：
  - 创建：新增文件时自然生成。
  - 重命名/移动：批量替换 `file_path` 前缀。
  - 删除：对 `file_path` 前缀批量逻辑删除（含 `SKILL.md` 的根目录禁止删除）。
- 目录与文件不可同名共存于同一父级。

---

### 2.4 版本（SkillVersion）

**定义**：Skill 在某次「提交/发布」时的完整快照，包含该版本下全部文件的不可变副本（存于 `skill_version_file`）。

**关键属性**：
- `versionNo`：版本号（语义化 `MAJOR.MINOR.PATCH` 或自增快照号）。
- `remark`：版本说明/变更摘要。
- `isReleased`：该版本是否曾上线。
- `creator` / `createTime`：创建人与创建时间。

**业务规则**：
- 每次「提交版本」或「上线」生成新版本快照。
- 历史版本只读，不可修改，可查看/对比/回滚/删除（删除需谨慎）。
- 同一 Skill 可存在多个版本；`currentVersion` 指向当前生效版本。
- 支持版本间文件差异对比（Diff）。

---

### 2.5 发布状态（Release）

**定义**：Skill 的生命周期状态，决定其是否可被 Agent 运行时消费。

**状态机**：
```
草稿(Draft) ──上线──> 已上线(Online)
已上线 ──下线──> 已下线(Offline)
已下线 ──重新上线(指定版本)──> 已上线(Online)
任意态(除已上线) ──删除──> 已删除(逻辑)
```

**业务规则**：
- 只有「校验通过（含 `SKILL.md` 且 frontmatter 合法）」的 Skill 可上线。
- 已上线 Skill 的线上内容来自其 `currentVersion` 快照，编辑草稿不影响线上。
- 上线时必须指定版本；支持「上线新版本」或「回滚到历史版本」。
- 下线后 Agent 不可再加载该 Skill。

---

## 三、功能需求

### 3.1 Skill 创建与基本信息管理（CRUD）
- **创建 Skill**：填写名称、描述、分类、标签；系统自动初始化根目录并生成空白 `SKILL.md`。
- **编辑基本信息**：修改名称、描述、分类、标签。
- **查询/列表**：支持按名称、分类、标签、状态、创建人筛选与分页。
- **删除 Skill**：逻辑删除；已上线需先下线。
- **详情查看**：展示元信息、目录树、当前版本、状态、历史版本列表。

### 3.2 Skill 文件管理（增删改查）
- **新增文件**：在指定目录下新建文件，选择类型并编辑内容；校验路径唯一性。
- **编辑文件**：在线编辑内容，实时/保存更新；`SKILL.md` 保存时校验 frontmatter。
- **查看文件**：查看内容、大小、路径、更新时间、所属版本。
- **删除文件**：单文件删除（禁删 `SKILL.md`），含二次确认。
- **重命名/移动**：跨目录移动文件，自动更新 `path`。
- **搜索文件**：在 Skill 内按文件名/内容模糊搜索。

### 3.3 目录关系管理
- **创建目录**：在任意层级新建子目录。
- **重命名/移动目录**：同步更新子文件 `path`。
- **删除目录**：递归删除目录树（风险确认）。
- **目录树展示**：可视化树形结构，支持展开/折叠、拖拽调整层级。
- **路径唯一与层级约束**：同父级目录/文件互斥；限制最大嵌套深度。

### 3.4 导入 / 导出
- **导出 Skill**：将单个（或全部）Skill 打包为可分发文件（如 `.zip` / 标准目录结构），含 `SKILL.md`、附属文件、元信息；导出内容取自指定版本（默认当前生效版本或草稿）。
- **导入 Skill**：
  - 支持从 `.zip` 或目录结构导入；解析并重建目录树与文件。
  - 导入校验：`SKILL.md` 存在且 frontmatter 合法；文件类型受支持。
  - 冲突策略：同名技能（`name`）时可选「覆盖（新版本）」或「另存为新 Skill」。
  - 导入后默认为「草稿」状态，需经发布流程上线。
- **批量操作**：支持多选 Skill 批量导出；支持模板导出（空 Skill 骨架）。

### 3.5 上线 / 下线（发布管理）
- **上线**：由创建人指定版本发布为线上生效版本，状态置「已上线」；仅校验通过的 Skill 可上线。
- **下线**：由创建人将 Skill 从线上移除，状态置「已下线」；保留历史版本。
- **重新上线/回滚**：已下线后可选历史版本重新上线。

### 3.6 版本管理
- **提交版本**：将当前草稿固化为一个只读版本快照，填写变更说明。
- **版本列表**：查看全部版本、版本号、说明、时间、是否曾上线。
- **版本查看/对比**：查看某版本完整内容；支持两版本间文件 Diff。
- **版本回滚**：将历史版本恢复为当前草稿（或一键上线为生效版本）。
- **版本删除**：删除不再需要的历史版本（保留至少可回溯的版本）。

## 四、查询与检索场景
1. 按名称/分类/标签/状态筛选 Skill 列表。
2. 在 Skill 内按文件名/内容搜索文件。
3. 查看某 Skill 的完整目录树。
4. 查看某 Skill 的全部历史版本及上线情况。
5. 查看某文件在指定版本中的内容。
6. 版本差异对比（Diff）。
7. 仅检索「已上线」Skill（供 Agent 运行时消费）。

---

## 五、权限
- **权限**：创建人（`create_user_id`）拥有 Skill 的全部操作权（编辑、上线、下线、版本管理）。
- **审计字段**（所有核心实体）：`create_user_id`、`create_time`、`update_user_id`、`update_time`、`deleted_flag`。

---

## 六、非功能性需求与约束
- **数据隔离**：草稿态与线上态数据隔离，编辑不影响运行。
- **完整性**：`SKILL.md` 与合法 frontmatter 是上线的硬性前置条件。
- **唯一性**：Skill 内文件路径唯一。
- **层级约束**：目录嵌套深度、单 Skill 文件数量、单文件大小设上限（可配置）。
- **可分发**：导入/导出格式标准化，保证跨环境可迁移。
- **可追溯**：基于版本快照，版本变更可回滚。
- **兼容性**：仅接受受支持文件类型；未知类型拒绝导入或标记为「其他」。

---

## 七、数据表设计（MySQL）

> 规范遵循项目《MySQL 数据库开发规范》：BIGINT 自增主键、字段默认 NOT NULL、审计字段齐全、逻辑删除 `deleted_flag`、引擎 InnoDB、字符集 utf8mb4。
> 字典类字段（`category` 分类、`file_type` 文件类型、`status` 状态枚举）复用现有 `sys_dict` 字典表；状态枚举取值：0-草稿 / 1-已上线 / 2-已下线。

### 7.1 skill（技能主表）
```sql
CREATE TABLE `skill` (
  `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `name`            VARCHAR(128) NOT NULL COMMENT '技能名称（对应 SKILL.md frontmatter name，兼作引用标识）',
  `description`     VARCHAR(512) NOT NULL DEFAULT '' COMMENT '技能描述（对应 SKILL.md frontmatter description）',
  `category`        VARCHAR(32)  NOT NULL DEFAULT '' COMMENT '分类（sys_dict 字典编码）',
  `tags`            JSON        NULL COMMENT '标签（JSON 数组，如 ["数据库","规范"]）',
  `status`          TINYINT      NOT NULL DEFAULT 0 COMMENT '状态: 0-草稿,1-已上线,2-已下线',
  `current_version` BIGINT       DEFAULT NULL COMMENT '当前线上生效版本ID（关联 skill_version.id）',
  `create_user_id`  BIGINT       NOT NULL COMMENT '创建人',
  `create_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_user_id`  BIGINT       DEFAULT NULL COMMENT '更新人',
  `update_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_flag`    TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '删除状态: 0-未删,1-已删',
  PRIMARY KEY (`id`),
  KEY `idx_skill_status` (`status`),
  KEY `idx_skill_category` (`category`),
  KEY `idx_skill_tags` ((CAST(`tags` AS CHAR(64) ARRAY)))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='技能主表';
```

### 7.2 目录结构（不单独建表，由文件路径派生）
技能包内的目录即文件路径的前缀，不单独建表。目录树由 `skill_file.file_path` 解析得出；目录的创建/重命名/移动/删除均通过对 `file_path` 做前缀批量操作实现：
- **创建目录**：在新增文件时自然生成（空目录打包导出无意义，不持久化）。
- **重命名/移动目录**：`UPDATE skill_file SET file_path = REPLACE(file_path, :oldPrefix, :newPrefix) WHERE skill_id = ? AND file_path LIKE CONCAT(:oldPrefix, '%')`（事务内执行，保持前缀边界）。
- **删除目录**：`UPDATE skill_file SET deleted_flag = 1 WHERE skill_id = ? AND file_path LIKE CONCAT(:prefix, '%')`；含 `SKILL.md` 的根目录禁止删除。

### 7.3 skill_file（草稿文件表）
```sql
CREATE TABLE `skill_file` (
  `id`           BIGINT      NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `skill_id`     BIGINT      NOT NULL COMMENT '所属技能（关联 skill.id）',
  `file_path`    VARCHAR(512) NOT NULL COMMENT '文件相对路径（如 scripts/run.py，含文件名，目录为路径前缀）',
  `file_name`    VARCHAR(255) NOT NULL COMMENT '文件名',
  `file_type`    VARCHAR(32) NOT NULL DEFAULT 'text' COMMENT '文件类型（sys_dict: markdown/json/text/code/其他）',
  `content`      LONGTEXT    COMMENT '文件内容（文本/代码，存库）',
  `content_size` INT         NOT NULL DEFAULT 0 COMMENT '内容字节大小',
  `is_entry`     TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '是否入口文件 SKILL.md: 0-否,1-是',
  `create_user_id` BIGINT    NOT NULL COMMENT '创建人',
  `create_time`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_user_id` BIGINT    DEFAULT NULL COMMENT '更新人',
  `update_time`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_flag` TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '删除状态',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_skill_file` (`skill_id`, `file_path`),
  KEY `idx_skill_file_path` (`skill_id`, `file_path`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='技能草稿文件表';
```

### 7.4 skill_version（版本表）
```sql
CREATE TABLE `skill_version` (
  `id`          BIGINT      NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `skill_id`    BIGINT      NOT NULL COMMENT '所属技能（关联 skill.id）',
  `version_no`  VARCHAR(32) NOT NULL COMMENT '版本号（语义化 MAJOR.MINOR.PATCH 或自增快照号）',
  `remark`      VARCHAR(512) NOT NULL DEFAULT '' COMMENT '版本说明/变更摘要',
  `is_released` TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '是否曾上线: 0-否,1-是',
  `create_user_id` BIGINT   NOT NULL COMMENT '创建人',
  `create_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_user_id` BIGINT   DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_flag` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '删除状态',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_skill_version` (`skill_id`, `version_no`),
  KEY `idx_skill_version_skill` (`skill_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='技能版本表';
```

### 7.5 skill_version_file（版本文件快照表）
```sql
CREATE TABLE `skill_version_file` (
  `id`           BIGINT      NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `version_id`   BIGINT      NOT NULL COMMENT '所属版本（关联 skill_version.id）',
  `file_path`    VARCHAR(512) NOT NULL COMMENT '文件相对路径（快照时刻）',
  `file_name`    VARCHAR(255) NOT NULL COMMENT '文件名',
  `file_type`    VARCHAR(32) NOT NULL DEFAULT 'text' COMMENT '文件类型',
  `content`      LONGTEXT    COMMENT '文件内容快照（不可变副本）',
  `content_size` INT         NOT NULL DEFAULT 0 COMMENT '内容字节大小',
  `is_entry`     TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '是否入口文件 SKILL.md',
  `create_time`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `deleted_flag` TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '删除状态',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_skill_vf` (`version_id`, `file_path`),
  KEY `idx_skill_vf_version` (`version_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='技能版本文件快照表';
```

### 7.6 表关系与关键约束
```
skill (技能) ──1:N──> skill_file (草稿文件，路径含目录前缀)
skill ──1:N──> skill_version (版本)
skill_version ──1:N──> skill_version_file (版本文件快照)
skill.current_version ──N:1──> skill_version.id
```
- **标签存主表（JSON）**：标签以 JSON 数组存于 `skill.tags`（如 `["数据库","规范"]`）；按标签过滤用 `JSON_CONTAINS(tags, '"数据库"')` 或 `'数据库' MEMBER OF(tags)`，并建多值索引 `idx_skill_tags`（CAST(tags AS CHAR(64) ARRAY)）支持高效检索；无标签时存空数组 `[]`。
- **目录由路径派生**：不单独建目录表；目录树由 `skill_file.file_path` 的前缀解析获得，目录的增删改均等价于对 `file_path` 做前缀批量操作（见 7.2）。
- **草稿/线上隔离**：`skill_file` 为可编辑工作副本；上线时将其全量复制进 `skill_version_file` 生成不可变快照，`skill.current_version` 指向该版本，Agent 仅读取快照。
- **唯一性**：`(skill_id, file_path)`、`(skill_id, version_no)`、`(version_id, file_path)` 组合唯一。
- **入口约束**：`is_entry=1` 的文件（`SKILL.md`）保存时校验 frontmatter；上线前必须存在且合法。
- **级联逻辑删除**：删除目录时对 `file_path` 前缀批量置 `deleted_flag=1`；版本快照一经生成不可变，仅允许逻辑删除整版本。
- **索引覆盖查询**：列表筛选走 `status`/`category` 索引；标签过滤走 `tags` 列 LIKE 匹配；目录树由 `file_path` 前缀解析；文件搜索走 `file_path`/`file_name` 模糊匹配。
